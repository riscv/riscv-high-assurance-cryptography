You are conducting a rigorous, adversarial technical review of a draft document describing a proposed security-critical RISC-V ISA extension. This document is contained in the src/ directory of this project.  The root file is ace.adoc. Consider only following files for the purpose of this task

Recall that the format of an SCC is

. one 128-bit block: Metadata Header, short MDH, contains also information about the lengths n and m. One or both of these can be zero
. one 128-bit block: SIV1 (we use a variant of AES-GCM-SIV)
. n 128-bit blocks:  Context1[0..n-1]
. if m != 0: one 128-bit block: SIV2
. one 128-bit block: IMPQUAL
. m 128-bit blocks:  Context2[0..m-1]

We do not know what to do if we allow ace.mgmt to be interrupted.

Perform an analysis of how an attacker could break the confidentiality of a SCC by interrupting ace.mgmt.

Determine which information is necessary in order to allow secure interruption and resumption of ace.mgmt.
In particular:
. which information needs to be saved and restored at context switch.
. what to save of the CRs in partially completed configuration operations.

Do we need to save and restore SIV1 and, if existing in the currently managed CR, SIV2 and IMPQUAL?
Do we need to keep track of a "thermometer" for the partially completed SCC operations, keep it in the MDH?
I suggest that, when we export the MDH of a partially imported or exported CR, the MDH should contain said thermometer somewhere and be authenticated, even if only the MDH is authenticated using a single-block MAC, since at the end of an import, the entire data will be authenticated in its entirety again.
The thermometer could be a block count and be stored in the _AuxInfo_ field of the MDH, possibly overwriting its previous contents. This is not a problem since we can move the information ML-KEM and ML-DSA stores there to some field in the content.

Consider the following cases:
. an export is interrupted and then the context switch handler needs to export the already-partially-exported CR.
. an import is interrupted and then the context switch handler needs to export the already-partially-imported CR.

Write procedures for provisioning, import, export. Prove their correctness against malicious users. A malicious user is allowed to make the contents of a CR unavailable by tampering with the MDH or the content itself. However, the confidentiality of the CR content must be preserved, and the malicious user shall not be able to forge content that would authenticate successfully.
