_This chapter is informative._ The examples follow the conventions of
<<Zkl-notation.adoc#KLEE-Notation>>; in particular, a value loaded into a vector register holds the
byte at the lowest address in its least significant bits.
The listings assume RV64, on which a 64-bit operand, such as the destination of `kl.getst` or the auxiliary input of a Form B `kl.setst`, is one GPR; on RV32 it is a GPR pair whose first register number is even (Rule <<Zkl-ISA-unpriv.adoc#KLEE-GR-multiple-GPRs>>).

[[KLEE-management-code-snippets]]
== Code for Locker Configuration and Export Operations

[WARNING]
====
These examples are being rewritten. They are not yet definitive.
====

This subsection illustrates the intended instruction sequences for locker configuration and export operations.
They show the main operation logic and error detection, but not application-specific error management, and can be packaged into libraries or OS APIs to avoid increasing application code size.

Registers:::
GPR `t0` holds the number of the locker to be provisioned, imported or exported, and GPR `t6` points to the 16-byte aligned memory location of the PI or SCC (<<Zkl-ISA-unpriv.adoc#KLEE-instructions-memory>>).
The MDH is loaded and stored with `ld` and `sd`, and passed in the GPR pair `s5:s4`; on RV32 it takes a GPR quartet (Rule <<Zkl-ISA-unpriv.adoc#KLEE-GR-multiple-GPRs>>).

Naming the locker:::
The routines never name the locker: on entry they save `klmanagedlocker` and write the locker number to it, and every KLEE instruction then acts on that locker (Rules <<Zkl-ISA-unpriv.adoc#KLEE-GR-locker-less-transfers>> and <<Zkl-ISA-unpriv.adoc#KLEE-GR-klmanagedlocker-override>>).
`kl.load`, `kl.store`, `kl.mvin` and `kl.mvout` have no locker operand, and `kl.mgmt`, `kl.getst`, `kl.getmd` and `kl.size` name the managed locker `KLML`, which requires no `Zklind`.
Since a clear resets `klmanagedlocker` to 32, the routines write it again before every opening, at `restart` for a provisioning or an import: a `KLML` opening raises an illegal-instruction exception when `klmanagedlocker` = 32, and otherwise opens the locker it names, a Valid one included (Rule <<Zkl-ISA-unpriv.adoc#KLEE-GR-klml-openings>>).
On exit they restore the saved value, as Rule <<Zkl-ISA-unpriv.adoc#KLEE-SR-klmanagedlocker-finish>> requires of software that has finished a management operation; a routine can thus be called from a handler that has saved the interrupted operation (<<Zkl-ISA-unpriv.adoc#KLEE-state-save-and-restore-order>>), including for a nested export or import of the locker that operation manages.

Checking the _State_:::
+
--
After each management instruction, the code reads the _State_ of the locker with `kl.getst`.
If a handler has meanwhile cleared the locker or set it to an Error State, a following `kl.mvin`, `kl.mvout`, `kl.load`, `kl.store` or `kl.mgmt`, other than an opening, performs no operation (Rule <<Zkl-ISA-unpriv.adoc#KLEE-GR-cleared-under-management>>), and the check detects the change:

* after a clear, `KLML` reads as an _Unconfigured_ locker, so the check finds _State_ 0: a provisioning or an import restarts, and an export, whose CC the clear has destroyed, branches to `handle_errors`;
* after an Error State, or the completing `kl.mgmt`, `KLML` still names the locker, so the check reads its final _State_, and an Error State abandons the operation.

Only the check after the last instruction is required; the earlier checks only react sooner.
The code may bound the number of restarts and branch to its error handling once the bound is reached; this is a matter of robustness only, since system software must let the operation complete (Rule <<Zkl-ISA-unpriv.adoc#KLEE-SR-no-unconditional-clear>>).
--

Error handling:::
The code at `handle_errors` is not shown.
It writes 0 to `klstart`, which a `kl.mvin` or `kl.mvout` loop leaves at its last transfer point, and restores `klmanagedlocker` as the routines do on exit.
If the locker is still in a Configuration State, it clears a locker being provisioned or imported, and completes the export of a locker being exported with the saved MDH, which restores the locker.

=== Provisioning

The provisioning code assumes that the Content immediately follows the MDH in memory.
The MDH of the PI carries _State_ = _Unconfigured_ (0); the completing `kl.mgmt` sets _Ready_.

*Provisioning Code (`Zklmv`)*
----
# t5 holds the length of the PI's Content (hence, excluding the MDH) in bytes.
# t5 can be zero. The caller constructed the PI and so knows this length.
# t5 is never modified, so the working count and pointer can be re-derived
# from it whenever the operation is restarted.

  ld        s4, 0(t6)             # load MDH[63:0] from memory
  ld        s5, 8(t6)             # load MDH[127:64] from memory
  li        t3, 0x30              # const useful to determine Error States
  csrr      s8, klmanagedlocker   # save the caller's value: the routine may
                                  # run inside another management operation

restart:
  csrw      klmanagedlocker, t0   # name the locker: every KLEE instruction
                                  # below acts on it; a clear resets it to 32
  kl.mgmt   KLML, #kl_cfg_provisioning, s5:s4 # start provisioning, load MDH
  kl.getst  t2, KLML              # get _State_ field from MDH
  beqz      t2, restart           # locker cleared: must restart
  andi      t2, t2, 0x38          # Check the three top bits of State
  beq       t3, t2, handle_errors # Error State: provisioning ended

  addi      t4, t6, 16            # source pointer: first byte after MDH
  mv        s1, t5                # working byte count, re-derived from t5
                                  # on restart

  vsetvli   s6, zero, e8, m1, ta, ma # s6 = VLMAX
vloop:
  mv        s2, s1
  bleu      s2, s6, 1f
  mv        s2, s6
1:
  vsetvli   s2, s2, e8, m1, ta, ma # AVL <= VLMAX, so vl = AVL, multiple of 16
  vle8.v    v1, (t4)              # load a chunk of the PI
  kl.mvin   v1                    # move it into the locker
  add       t4, t4, s2            # bump the source pointer
  sub       s1, s1, s2            # decrement the bytes still to load
  kl.getst  t2, KLML
  beqz      t2, restart           # locker cleared: must restart
  andi      t2, t2, 0x38          # Three top bits -> Error or Management
  beq       t3, t2, handle_errors # *new* Error State
  bnez      s1, vloop

  kl.mgmt   KLML, #kl_cfg_management_end # complete provisioning
                                  # and possibly reconstruct data
  kl.getst  t2, KLML
  beqz      t2, restart           # locker cleared: must restart
  andi      t2, t2, 0x38
  beq       t3, t2, handle_errors # catches errors at completion (e.g., SKS)

finished:
  csrw      klmanagedlocker, s8   # restore the caller's value
# The locker is Ready, or in Failure after a data error at completion. Any
# Error State met above is new, since the PI carried State = Unconfigured:
# handle_errors decides the course of action.
----

*Provisioning Code (`Zklmem`)*
----
  ld        s4, 0(t6)             # load MDH[63:0] from memory
  ld        s5, 8(t6)             # load MDH[127:64] from memory
  li        t3, 0x30              # const useful to determine Error States
  csrr      s8, klmanagedlocker   # save the caller's value

restart:
  csrw      klmanagedlocker, t0   # name the locker (a clear resets it to 32)
  kl.mgmt   KLML, #kl_cfg_provisioning, s5:s4 # start prov. and load MDH
  kl.getst  t2, KLML
  beqz      t2, restart           # locker cleared: must restart
  andi      t2, t2, 0x38          # Check the three top bits of State
  beq       t3, t2, handle_errors # Error State?

  # Assume that the Content directly follows the MDH in memory.
  kl.load   16(t6), x0            # load rest of PI into the locker
  kl.getst  t2, KLML
  beqz      t2, restart           # locker cleared means force restart
  andi      t2, t2, 0x38
  beq       t3, t2, handle_errors
  kl.mgmt   KLML, #kl_cfg_management_end # complete provisioning
                                  # and possibly reconstruct data
  kl.getst  t2, KLML
  beqz      t2, restart           # locker cleared: must restart
  andi      t2, t2, 0x38
  beq       t3, t2, handle_errors # catches errors at completion (e.g., SKS)
finished:
  csrw      klmanagedlocker, s8   # restore the caller's value
----

=== Export

*Export Code (`Zklmv`)*
----
  li         t3, 0x30             # to determine Error States
  csrr       s8, klmanagedlocker  # save the caller's value
  csrw       klmanagedlocker, t0  # name the locker for all that follows
  kl.size    s1, KLML             # TOTAL size to export
  beqz       s1, handle_errors    # 0 means the locker is unconfigured

  {...}  # here code that allocates the buffer to store the exported data

  kl.getmd   s5:s4, KLML          # get MDH, including its _State_
  srli       t2, s4, 18           # _State_ of that MDH, bits [23:18]
  andi       t2, t2, 0x3f
  beqz       t2, handle_errors    # locker cleared since kl.size
  sd         s4, 0(t6)            # store MDH[63:0] to memory
  sd         s5, 8(t6)            # store MDH[127:64] to memory

  addi       t6, t6, 16           # point to next memory region
  li         s3, 16               # s3 = 16 (size of MDH)
  beq        s1, s3, done         # only the MDH to store (e.g., Error State)

  kl.mgmt    KLML, #kl_cfg_exporting  # start exporting
  kl.getst   t2, KLML
  beqz       t2, handle_errors    # locker cleared: the CC is lost
  andi       t2, t2, 0x38
  beq        t3, t2, handle_errors # Error State set meanwhile
  kl.size    t2, KLML             # size now that the export is open
  bne        t2, s1, handle_errors # ADS changed since the buffer was sized
  addi       s1, s1, -16          # adjust size to remove the MDH
  mv         t4, t6               # destination: first byte after stored MDH
  vsetvli    s6, zero, e8, m1, ta, ma # s6 = VLMAX
store_loop:
  mv         s2, s1
  bleu       s2, s6, 1f
  mv         s2, s6
1:
  vsetvli    s2, s2, e8, m1, ta, ma # AVL <= VLMAX, so vl = AVL, multiple of 16
  kl.mvout   v2                   # move chunk out of the locker,
                                  # advance klstart
  vse8.v     v2, (t4)             # store it
  add        t4, t4, s2           # bump the destination pointer
  sub        s1, s1, s2           # decrement the bytes still to store
  kl.getst   t2, KLML
  beqz       t2, handle_errors    # locker cleared: the CC is lost
  andi       t2, t2, 0x38
  beq        t3, t2, handle_errors
  bnez       s1, store_loop

finished:
  # Restore _State_ from the saved MDH.
  kl.mgmt    KLML, #kl_cfg_management_end, s5:s4
  kl.getst   t2, KLML
  beqz       t2, handle_errors    # locker cleared: the CC is lost
  andi       t2, t2, 0x38
  beq        t3, t2, handle_errors # catches `kl_state_mgmt_auth`
done:
  csrw       klmanagedlocker, s8  # restore the caller's value
----

[WARNING]
====
Incomplete procedure, like all the others in management.
A locker in an Error State is covered: only its MDH is stored.
A locker under management (partially provisioned, imported or exported) is exported by the same sequence,
but the caller must also save `klstart` before the opening `kl.mgmt`, which clears it, and restore it after the re-import
(<<Zkl-ISA-unpriv.adoc#KLEE-state-save-and-restore-order>>); this is not shown.
====

*Export Code (`Zklmem`)*
----
# Up to the size check after the opening kl.mgmt, and from finished on, the
# code is that of the Zklmv version.
  kl.store  0(t6), x0             # store SIV, IMPQUAL, SIV2 and Content
                                  # of the locker (Xl = x0)
  kl.getst  t2, KLML
  beqz      t2, handle_errors     # locker cleared: the CC is lost
  andi      t2, t2, 0x38
  beq       t3, t2, handle_errors
----

=== Import

*Import Code (`Zklmv`)*
----
  ld         s4, 0(t6)            # load MDH[63:0] from memory
  ld         s5, 8(t6)            # load MDH[127:64] from memory
  li         t3, 0x30             # to determine Error States
  srli       s7, s4, 18           # _State_ of the saved MDH, bits [23:18]
  andi       s7, s7, 0x38         # s7 = 0x30: image of an Error-State locker
  csrr       s8, klmanagedlocker  # save the caller's value

restart:
  csrw      klmanagedlocker, t0   # name the locker (a clear resets it to 32)
  kl.mgmt   KLML, #kl_cfg_importing, s5:s4    # open locker for import, load MDH
  kl.getst  t2, KLML
  beqz      t2, restart           # locker cleared means force restart
  andi      t2, t2, 0x38
  bne       t3, t2, 2f            # three top bits of _State_ = 110 ?
  beq       t3, s7, success       # yes, as saved: the short import is complete,
                                  # with this one kl.mgmt and no load
  j         handle_errors         # yes, but new (e.g., invalid Metadata)
2:
  kl.size   s1, KLML              # size of the image the locker accepts,
                                  # without a dropped ADS
  beqz      s1, restart           # 0: locker cleared since the check
  addi      t4, t6, 16            # first byte after the MDH
  addi      s1, s1, -16           # image size to load, without the MDH

  vsetvli   s6, zero, e8, m1, ta, ma # s6 = VLMAX
vloop:
  mv        s2, s1
  bleu      s2, s6, 1f
  mv        s2, s6
1:
  vsetvli   s2, s2, e8, m1, ta, ma # AVL <= VLMAX, so vl = AVL, multiple of 16
  vle8.v    v2, (t4)              # load a chunk of the SCC
  kl.mvin   v2                    # move it into the locker, advance klstart
  add       t4, t4, s2
  sub       s1, s1, s2
  kl.getst  t2, KLML
  beqz      t2, restart           # locker cleared means force restart
  andi      t2, t2, 0x38
  beq       t3, t2, handle_errors
  bnez      s1, vloop

  kl.mgmt   KLML, #kl_cfg_management_end, s5:s4 # decrypt and auth SCC
                                  # and restore _State_ from the saved MDH
  kl.getst  t2, KLML
  beqz      t2, restart           # locker cleared means force restart
  andi      t2, t2, 0x38
  beq       t3, t2, handle_errors # catches "Authentication Failed"

success:
  csrw      klmanagedlocker, s8   # restore the caller's value
----

*Import Code (`Zklmem`)*
----
  ld        s4, 0(t6)             # load MDH[63:0] from memory
  ld        s5, 8(t6)             # load MDH[127:64] from memory
  li        t3, 0x30              # to determine Error States
  srli      s7, s4, 18            # _State_ of the saved MDH, bits [23:18]
  andi      s7, s7, 0x38          # s7 = 0x30: image of an Error-State locker
  csrr      s8, klmanagedlocker   # save the caller's value

restart:
  csrw      klmanagedlocker, t0   # name the locker (a clear resets it to 32)
  kl.mgmt   KLML, #kl_cfg_importing, s5:s4    # open locker for import, load MDH
  kl.getst  t2, KLML
  beqz      t2, restart           # locker cleared means force restart
  andi      t2, t2, 0x38
  bne       t3, t2, 2f            # three top bits of _State_ = 110 ?
  beq       t3, s7, success       # yes, as saved: the short import is complete
  j         handle_errors         # yes, but new (e.g., invalid Metadata)
2:
  addi      t4, t6, 16            # first byte after the MDH

  kl.load   0(t4), x0             # load rest of SCC into the locker
  kl.getst  t2, KLML
  beqz      t2, restart           # locker cleared means force restart
  andi      t2, t2, 0x38
  beq       t3, t2, handle_errors
  kl.mgmt   KLML, #kl_cfg_management_end, s5:s4 # decrypt and auth locker,
                                  # if necessary complete it
  kl.getst  t2, KLML
  beqz      t2, restart           # locker cleared means force restart
  andi      t2, t2, 0x38
  beq       t3, t2, handle_errors # catches `kl_state_mgmt_auth`

success:
  csrw      klmanagedlocker, s8   # restore the caller's value
----

During the provisioning and import procedures, the validity of the whole MDH is checked by the opening `kl.mgmt`, which receives it in Form D (<<Zkl-ISA-unpriv.adoc#KLEE-MVR-open>>), except for the image of a locker in an Error State, of which only the _State_ is checked (<<Zkl-ISA-unpriv.adoc#KLEE-error-state-transfer>>).
The conditions evaluated at completion — SKS resolution at provisioning, authentication at import — can still transition the locker to an Error State upon executing `kl.mgmt KLML, #kl_cfg_management_end`, which the `kl.getst` after that instruction detects, as it detects a clear or an Error State set at any earlier point.
A data error found by a check that the Machine attaches to a field of the PI or SCC leaves the locker in _Failure_ instead (Rule <<Zkl-ISA-unpriv.adoc#KLEE-GR-completion-state>>), which these listings do not test.

[[KLEE-ECB-mode-example]]
== Electronic Codebook Modes (Direct Encryption/Decryption)

The following pseudocode illustrates how to use an ECB CC to encrypt data with a block cipher.
Here, as in most other examples, we assume the block cipher has a width of 128 bits (`KLLEN` is also 128).
The uppercase `IMPORT` instruction is a placeholder for an import code snippet, library, or API call.

[[KLEE-pseudocode-ECB-encryption]]
.Simple Example: Encryption with no Authentication
----
- Call OS API to get the necessary SCC. Assume X5 points to the SCC.
- Allocate memory for ciphertext buffer.

  vsetivli zero, 4, e32, m1, ta, ma        // Use 128-bit vectors
  IMPORT K0, (X5)                          // Import the SCC into locker K0
  kl.getst X1, K0
  if (48 <= X1 <= 55) then: handle error

  kl.setst K0, #kl_state_encrypt         // Configure locker to encrypt
  kl.getst X1, K0
  if (48 <= X1 <= 55) then: handle error

  // assume plaintext in whole blocks
  foreach(i from 0 to len_in_bytes(plaintext)/16-1) do:
    V0 ← plaintext[16*i .. 16*i+15]
    kl.exec V0, K0, V0                   // Encrypt one block of plaintext
    ciphertext[16*i .. 16*i+15] ← V0
----

[[KLEE-keystream-modes-example]]
== CTR/XCTR Keystream Generation

[[KLEE-pseudocode-keystream-modes]]
.Encrypt with Keystream Generation
----
// Acquire payload, initialize
- Info: plaintext = *PT
- Process gets a Keystream Generation CC from an API. X5 = pointer to the CC.
- Allocate memory for ciphertext buffer CT (if not same as PT).

  vsetivli zero, 4, e32, m1, ta, ma         // Use 128-bit vectors
  IMPORT K0, (X5)

  // The next operations set the nonce
  V1 ← nonce
  kl.setst K0, #kl_state_operate, V1

  // Compute keystream, use it to encrypt plaintext.  A final partial block
  // still takes a whole keystream block; the caller discards the bytes past
  // the end of PT.
  foreach(i from 0 to ceil(len_in_bytes(PT)/16)-1) do:
    V0 ← PT[16*i .. 16*i+15]
    kl.exec V1, K0
    V1 ← V1 xor V0
    CT[16*i .. 16*i+15] ← V1
----

== XEX/XTS modes

Only XEX encryption pseudocode is provided; decryption is similar
(here it is also assumed `b` = `KLLEN` = 128).

[[KLEE-pseudocode-basic-IV-mode]]
.Pseudocode for encryption in any IV-based non-authenticated mode without associated data
----
// Acquire payload and SCC, initialize
- Info: plaintext = *PT
- Call an API to get the corresponding SCC.  X5 = pointer to it.
- Allocate memory for ciphertext buffer CT (if not same as PT).

  vsetivli zero, 4, e32, m1, ta, ma      // Use 128-bit vectors
  IMPORT K0, (X5)

  V0 ← IV
  kl.setst K0, #kl_state_encrypt, V0 // Configure locker to encrypt, set tweak

  foreach(i from 0 to floor(len_in_bytes(PT)/16)-1) do:
    V0 ← PT[16*i .. 16*i+15]
    kl.exec V0, K0, V0                   // Encrypt one block of plaintext
    CT[16*i .. 16*i+15] ← V0
----

The loop covers whole blocks only: XEX has no partial-block state.
A data unit whose length is not a multiple of `b` is completed by ciphertext stealing, which software performs with further `kl.exec` on the same CC, and a `kl.clone` for decryption, as described in <<Zkl-ISA-machines.adoc#KLEE-XTS-from-XEX>>.

[[KLEE-GCM-mode-examples]]
== GCM Mode

In <<KLEE-pseudocode-GCM-encryption>> we show pseudocode for GCM encryption, again with
`b` = `KLLEN` = 128 and `c` = 32.

Associated data and plaintext/ciphertext are treated differently, as <<Zkl-ISA-machines.adoc#KLEE-GCM-mode>> requires.
The caller zero-fills the final block of the AD beyond its actual end, and `GHASH` absorbs that block whole.
For the PT and CT the caller must not rely on zero-padding: a final block shorter than `b` goes through State _Enc_Last_Block_ (or _Dec_Last_Block_ for decryption), so that no keystream bit past the end of the message is absorbed into `GHASH` or written out.

[[KLEE-pseudocode-GCM-encryption]]
.GCM Encryption
----
// Acquire payload, initialize
- Info: authenticated data = *AD, plaintext = *PT
- Process gets a GCM encryption CC from an API.  X5 = pointer to the CC.
- Allocate memory for ciphertext buffer CT (if not same as PT).

  vsetivli zero, 4, e32, m1, ta, ma         // Use 128-bit vectors
  IMPORT K0, (X5)               // Import (also computes the derived Auth Key)

  // Set the IV.  The Form B kl.setst carries its length in bits; the IV
  // itself is then absorbed by kl.exec.  This example assumes that the IV fits
  // in V0; a longer one is supplied by several kl.exec, each a multiple of
  // 16 bytes except the last.  When the last byte has been absorbed the
  // Machine computes J0 and moves to _Hash_Absorb_ by itself, so no kl.setst
  // is issued for that transition.

  X1 ← len_in_bits(IV)

  kl.setst K0, #kl_state_set_aux_value, X1
  X2 ← X1/8                                // len_in_bytes(IV)
  vsetvli  zero, X2, e8, m1, ta, ma        // KLLEN = 8*len_in_bytes(IV)
  V0 ← IV
  kl.exec K0, V0
  vsetivli zero, 4, e32, m1, ta, ma        // back to 128-bit vectors

  // Compute the AD contribution to the tag.
  // The caller has zero-filled the last block beyond the end of the AD.
  foreach(i from 0 to ceil(len_in_bytes(AD)/16)-1) do:
    V0 ← AD[16*i .. 16*i+15]
    kl.exec K0, V0                       // Absorb it into GHASH

  // Encrypt the whole blocks of the plaintext
  kl.setst K0, #kl_state_encrypt
  PT_fullblocks ← floor(len_in_bits(PT)/128)

  foreach(i from 0 to PT_fullblocks-1) do:
    V0 ← PT[16*i .. 16*i+15]
    kl.exec V1, K0, V0
    CT[16*i .. 16*i+15] ← V1

  // Fractional final block, if any. The plaintext is not zero-padded here.
  X1 ← len_in_bits(PT) mod 128
  if (X1 != 0) then:
    kl.setst K0, #kl_state_enc_last_block, X1
    V0 ← PT[16*PT_fullblocks .. 16*PT_fullblocks+ceil(X1/8)-1]
    kl.exec V1, K0, V0
    CT[16*PT_fullblocks .. 16*PT_fullblocks+ceil(X1/8)-1] ← V1

  // Absorb the lengths, finalize the tag, and read it out
  V1 ← bswap(bin(len_in_bits(PT), 64)) @ bswap(bin(len_in_bits(AD), 64))
  kl.setst K0, #kl_state_enc_tag_finalize, V1
  kl.exec V2, K0                          // V2 contains the tag
----

<<KLEE-pseudocode-GCM-decryption>> gives the code for GCM decryption, from the point where the AD has been absorbed; up to there, the code is that of <<KLEE-pseudocode-GCM-encryption>>.
// Decryption differs from encryption in three ways: the roles of `PT` and `CT` are
// reversed; States _Encrypt_ and _Enc_Last_Block_ are replaced by _Decrypt_ and
// _Dec_Last_Block_; and the tag is finalized and verified instead of being emitted, as shown
// below.
Note that no `kl.exec` is issued in State _Dec_Tag_Finalize_: the recomputed tag
stays inside the locker and is never made available to software on this path.

[[KLEE-pseudocode-GCM-decryption]]
.GCM Decryption
----
  // Decrypt the whole blocks of the ciphertext
  kl.setst K0, #kl_state_decrypt
  CT_fullblocks ← floor(len_in_bits(CT)/128)
  foreach(i from 0 to CT_fullblocks-1) do:
    V0 ← CT[16*i .. 16*i+15]
    kl.exec V1, K0, V0
    PT[16*i .. 16*i+15] ← V1

  // Fractional final block, if any.  The ciphertext is not zero-padded here.
  X1 ← len_in_bits(CT) mod 128
  if (X1 != 0) then:
    kl.setst K0, #kl_state_dec_last_block, X1
    V0 ← CT[16*CT_fullblocks .. 16*CT_fullblocks+ceil(X1/8)-1]
    kl.exec V1, K0, V0
    PT[16*CT_fullblocks .. 16*CT_fullblocks+ceil(X1/8)-1] ← V1

  // Absorb the lengths.  The tag is computed and retained inside the locker.
  V1 ← bswap(bin(len_in_bits(CT), 64)) @ bswap(bin(len_in_bits(AD), 64))
  kl.setst K0, #kl_state_dec_tag_finalize, V1

  // Supply the received tag; the comparison sets _Success_ or _Failure_
  V1 ← tag_from_payload
  kl.setst K0, #kl_state_hash_verify, V1
  kl.getst X1, K0
  if (X1 != kl_state_success) then:
     handle error     // Do not use the plaintext in case of error
----

We also show how to implement GCM encryption using an ECB CC, provided the vector ISA
supports carry-less binary multiplication.

[[KLEE-pseudocode-GCM-encryption-alternate]]
.Implementing GCM encryption using an ECB CC
----
// Acquire payload, initialize
- Info: authenticated data = *AD, plaintext = *PT
- Process gets an ECB encryption CC from an API.  X5 = pointer to the CC.
- Allocate memory for ciphertext buffer CT (if not same as PT).

  vsetivli zero, 4, e32, m1, ta, ma
  IMPORT K0, (X5)
  kl.setst K0, #kl_state_encrypt      // kl.exec encrypts only in _Encrypt_
  V0[95:0] ← IV                       // 96-bit IV in bytes 0..11
  V3 ← zeros(b)                       // “Auth Data 1”
  kl.exec V4, K0, V3                  // compute H

  // The caller has zero-filled the last block beyond the end of the AD.
  foreach(i from 0 to ceil(len_in_bytes(AD)/16)-1) do:
    V1 ← AD[16*i .. 16*i+15]
    V3 ← V3 xor V1
    V3 ← Galoismul(V4, V3)

  // Counter = 1 is used for E(K,J0), which is the tag mask: in this 96-bit
  // nonce version, the counter for the text starts at 2.

  counter ← 2
  PT_fullblocks ← floor(len_in_bytes(PT)/16)
  foreach(i from 0 to PT_fullblocks-1) do:
    V5 ← bswap(bin(counter,32)) @ V0[95:0]
    V1 ← PT[16*i .. 16*i+15]
    kl.exec V2, K0, V5                // create mask by encrypting the counter
    V1 ← V1 xor V2                    // CTR encrypt
    V3 ← V3 xor V1
    V3 ← Galoismul(V4, V3)
    CT[16*i .. 16*i+15] ← V1
    counter ← counter + 1

  // Fractional final block of r bytes, if any.  The ciphertext is truncated
  // to r bytes before it is absorbed and stored: GHASH absorbs the
  // zero-padded ciphertext, which is what SP 800-38D specifies.
  r ← len_in_bytes(PT) mod 16
  if (r != 0) then:
    V5 ← bswap(bin(counter,32)) @ V0[95:0]
    V1 ← PT[16*PT_fullblocks .. 16*PT_fullblocks+r-1]
    kl.exec V2, K0, V5
    V1 ← V1 xor V2
    V1 ← zeros(128-8*r) @ V1[8*r-1:0] // discard the keystream past the end
    V3 ← V3 xor V1
    V3 ← Galoismul(V4, V3)
    CT[16*PT_fullblocks .. 16*PT_fullblocks+r-1] ← V1

  V3 ← V3 xor (bswap(bin(len_in_bits(PT),64)) @ bswap(bin(len_in_bits(AD),64)))
  V3 ← Galoismul(V4, V3)
  V5 ← bswap(bin(1,32)) @ V0[95:0]    // J0 (counter 1), for the tag mask
  kl.exec V2, K0, V5
  tag ← V3 xor V2
----

[[KLEE-GCM-SIV-mode-examples]]
== GCM-SIV Mode

We show in <<KLEE-pseudocode-GCM-SIV-encryption>> how to perform AEAD encryption with a GCM-SIV CC (with `b` = `KLLEN` = 128).
<<KLEE-pseudocode-GCM-SIV-decryption>> is the corresponding pseudocode for decryption.

[[KLEE-pseudocode-GCM-SIV-encryption]]
.GCM-SIV Encryption
----
// Acquire payload, initialize
- Info: authenticated data = *AD
- Info: plaintext = *PT
- Call API to get the key from a key management applet or HW block.
- The API returns the SCC. Assume X5 is the pointer to it.
- Allocate memory for ciphertext buffer CT (if not same as PT).

  vsetivli zero, 4, e32, m1, ta, ma   // Use 128-bit vectors
  IMPORT K0, (X5)

  // Set the nonce, which also derives enc_key and auth_key.
  // Form C kl.setst: the nonce is the vector input of kl.setst.
  //  No kl.exec is issued in this state.

  V0 ← nonce
  kl.setst K0, #kl_state_set_aux_value, V0

  // Absorb the AD and then the plaintext into POLYVAL.
  // The caller has zero-padded the last block of each.

  kl.setst K0, #kl_state_hash_absorb
  foreach(i from 0 to ceil(len_in_bytes(AD)/16)-1) do:
    V0 ← AD[16*i .. 16*i+15]             // Load a block of associated data
    kl.exec K0, V0                       // Absorb it into POLYVAL

  foreach(i from 0 to ceil(len_in_bytes(PT)/16)-1) do:
    V0 ← PT[16*i .. 16*i+15]             // Load a block of plaintext
    kl.exec K0, V0                       // Absorb it into POLYVAL

  // Finalize the SIV.  The lengths are the *input* of a Form A kl.exec in
  // State _Enc_Tag_Finalize_, and the SIV is its output; they are not
  // absorbed by a further kl.exec in _Hash_Absorb_.
  kl.setst K0, #kl_state_enc_tag_finalize
  V0 ← bin(len_in_bits(PT), 64) @ bin(len_in_bits(AD), 64)
  kl.exec V2, K0, V0
  tag ← V2

  // Second pass: encrypt the whole blocks of the plaintext, with the SIV
  // as IV. The kl.exec above has already moved the locker to _Encrypt_;
  // a kl.setst naming _Encrypt_ would invalidate it.
  PT_fullblocks ← floor(len_in_bits(PT)/128)

  foreach(i from 0 to PT_fullblocks-1) do:
    V0 ← PT[16*i .. 16*i+15]             // Load a block of plaintext
    kl.exec V1, K0, V0                   // Encrypt the block
    CT[16*i .. 16*i+15] ← V1             // Store a block of ciphertext

  // Fractional final block, if any.  Unlike in the first pass, it must not
  // go through as a zero-padded whole block: _Enc_Last_Block_ writes no
  // keystream bit past the end of PT to CT.
  X1 ← len_in_bits(PT) mod 128
  if (X1 != 0) then:
    kl.setst K0, #kl_state_enc_last_block, X1
    V0 ← PT[16*PT_fullblocks .. 16*PT_fullblocks+ceil(X1/8)-1]
    kl.exec V1, K0, V0
    CT[16*PT_fullblocks .. 16*PT_fullblocks+ceil(X1/8)-1] ← V1
----

[[KLEE-pseudocode-GCM-SIV-decryption]]
.GCM-SIV Decryption
----
// Acquire payload, initialize
- Info: authenticated data = *AD
- Info: ciphertext = *CT
- Call an API to get the corresponding key from a key management entity.
- The API returns the SCC. Assume X5 is the pointer to it.
- Allocate memory for plaintext buffer PT (if not same as CT).

  vsetivli zero, 4, e32, m1, ta, ma      // Use 128-bit vectors
  IMPORT K0, (X5)

  // Set the nonce
  V0 ← nonce
  kl.setst K0, #kl_state_set_aux_value, V0

  // Set the received SIV, which serves as the IV of the decryption.
  V0 ← SIV
  kl.setst K0, #kl_state_set_aux_value_2, V0

  // Absorb the AD.  The caller has zero-padded the last block.
  kl.setst K0, #kl_state_hash_absorb
  foreach(i from 0 to ceil(len_in_bytes(AD)/16)-1) do:
    V0 ← AD[16*i .. 16*i+15]
    kl.exec K0, V0                       // Absorb it into POLYVAL

  // Decrypt the whole blocks; each recovered block is absorbed into POLYVAL
  kl.setst K0, #kl_state_decrypt
  CT_fullblocks ← floor(len_in_bits(CT)/128)
  foreach(i from 0 to CT_fullblocks-1) do:
    V0 ← CT[16*i .. 16*i+15]
    kl.exec V1, K0, V0
    PT[16*i .. 16*i+15] ← V1

  // Fractional final block, if any
  X1 ← len_in_bits(CT) mod 128
  if (X1 != 0) then:
    kl.setst K0, #kl_state_dec_last_block, X1
    V0 ← CT[16*CT_fullblocks .. 16*CT_fullblocks+ceil(X1/8)-1]
    kl.exec V1, K0, V0
    PT[16*CT_fullblocks .. 16*CT_fullblocks+ceil(X1/8)-1] ← V1

  // Absorb the lengths and verify, with a Form B kl.exec: the recomputed
  // SIV is compared internally against the one supplied above
  kl.setst K0, #kl_state_dec_tag_finalize
  V0 ← bin(len_in_bits(PT), 64) @ bin(len_in_bits(AD), 64)
  kl.exec K0, V0
  kl.getst X1, K0
  if (X1 != kl_state_success) then:
    handle error     // Do not use the plaintext if error
----

[[KLEE-OCB-mode-examples]]
== OCB Mode

In this section we show pseudocode for OCB encryption and decryption (`b` = `KLLEN` = 128).

[[KLEE-pseudocode-OCB-encryption]]
.OCB Encryption
----
// Acquire payload, initialize
- Info:
- authenticated data = *AD with bit length AD_len
- plaintext = *PT with bit length PT_len
- nonce N with bit length N_len
- tag length tag_len

- Process gets an OCB encryption CC from an API.  X5 = pointer to the CC.
- Allocate memory for ciphertext buffer CT (if not same as PT).

  vsetivli zero,4,e32,m1,ta,ma              // Use 128-bit vectors
  IMPORT K0, (X5)

  // The next operations set the nonce
  X1 ← N_len
  kl.setst K0, #kl_state_set_aux_value, X1
  V0 ← N
  kl.exec K0, V0

  // The next state change also sets the tag length
  X1 ← tag_len
  kl.setst K0, #kl_state_hash_absorb, X1

  AD_fullblocks ← floor(AD_len/128)
  PT_fullblocks ← floor(PT_len/128)

  // Compute AD contribution to tag
  foreach(i from 0 to AD_fullblocks-1) do:
    V0 ← AD[16*i .. 16*i+15]
    kl.exec K0, V0                       // Absorb it into hash

  X1 ← AD_len mod 128                    // Can be zero
  kl.setst K0, #kl_state_hash_last_block, X1

  if (X1 != 0) then:
    V0 ← AD[AD_fullblocks*16 .. AD_fullblocks*16+ceil(X1/8)-1]
    kl.exec K0, V0                       // Absorb the last AD block

  // Encrypt plaintext and continue computation of tag
  kl.setst K0, #kl_state_encrypt
  foreach(i from 0 to PT_fullblocks-1) do:
    V0 ← PT[16*i .. 16*i+15]
    kl.exec V1, K0, V0
    CT[16*i .. 16*i+15] ← V1

  X1 ← PT_len mod 128                    // Can be zero
  kl.setst K0, #kl_state_enc_last_block, X1

  if (X1 != 0) then:
    V0 ← PT[PT_fullblocks*16 .. PT_fullblocks*16+ceil(X1/8)-1]
    kl.exec V1, K0, V0              // Encrypt it and absorb it into the tag
    CT[PT_fullblocks*16 .. PT_fullblocks*16+ceil(X1/8)-1] ← V1
  else:
    kl.exec K0                           // Form D: finalize the tag only

  // _Enc_Last_Block_ transitions to _Enc_Tag_Finalize_ on its own, so no
  // kl.setst is issued here.
  kl.exec V1, K0                         // output tag
----

OCB decryption follows <<KLEE-pseudocode-OCB-encryption>> up to the final block, with the roles of `PT` and `CT` exchanged, and States _Decrypt_ and _Dec_Last_Block_ in place of _Encrypt_ and _Enc_Last_Block_;
<<KLEE-pseudocode-OCB-decryption-difference>> gives only the last step, which differs.
OCB has no _Dec_Tag_Finalize_ state: after the last block, _Dec_Last_Block_ transitions directly to
_Hash_Verify_, where the received tag is supplied, as shown below.

[[KLEE-pseudocode-OCB-decryption-difference]]
.OCB Decryption
----
  V1 ← tag                               // the tag received with the message
  kl.setst K0, #kl_state_hash_verify, V1 // compares it against checksum_P
  kl.getst X1, K0
  if (X1 != kl_state_success) then:      // do not use the plaintext if error
     handle error
----

[[KLEE-CMAC-mode-example]]
== CMAC Functions

[[KLEE-pseudocode-CMAC]]
.CMAC Computation
----
- Info: CMAC input = *M with bit length M_len
- Process gets a CMAC CC from an API. Assume X5 is the pointer to the CC.

  vsetivli zero, 4, e32, m1, ta, ma      // Use 128-bit vectors
  IMPORT K0, (X5)

  kl.setst K0, #kl_state_hash_absorb
  blocks    ← floor(M_len/128)
  remainder ← M_len mod 128
  if remainder == 0 and blocks > 0 then  // a whole number of full blocks:
    blocks    ← blocks - 1               // the last one is the "last block"
    remainder ← 128                  // a full last block takes no 10* padding

  foreach(i from 0 to blocks-1) do:
    V0 ← M[16*i .. 16*i+15]
    kl.exec K0, V0

  X1 ← remainder
  kl.setst K0, #kl_state_hash_last_block, X1
                                         // with X1 = 0 (empty message), it
                                         // pads and enters _Hash_Output_
  if remainder != 0 then:
    V0 ← M[16*blocks .. 16*blocks+ceil(remainder/8)-1]
    kl.exec K0, V0                       // absorbing it moves the CC to
                                         // _Hash_Output_ by itself
  kl.exec V0, K0                         // this is the CMAC value
----
